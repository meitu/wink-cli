直接提交当前会话修改到当前分支: `$ARGUMENTS`

## 执行规则

1. 把 `$ARGUMENTS` 视为必填备注。
2. 如果 `$ARGUMENTS` 为空，先向用户索要备注，不要自行编造。
3. 只在当前仓库和当前分支内操作。
4. 禁止创建分支、切换分支、rebase、reset、amend。
5. 默认提交当前会话中实际修改过的文件；如果备注中明确提到了文件路径或文件名，把这些文件也作为额外提交范围。
6. 额外提交的文件必须能在仓库内唯一定位；如果同名文件有多个候选，先停下来向用户确认。
7. 额外提交的文件只有在当前工作区存在改动时才加入提交；未改动文件不要强行提交，但要在结果里说明。

## 文件识别规则

1. 识别备注中的仓库相对路径、绝对路径、以及带扩展名的文件名，例如 `src/logic/VideoBase.cpp`、`D:\project\wink_desktop\src\logic\VideoBase.cpp`、`VideoBase.cpp`。
2. 优先按完整路径匹配；只有没有路径时，才按文件名在仓库内搜索。
3. 同一文件被多次提到时只保留一次。
4. 识别出的文件既用于扩大 `git add` 范围，也必须从最终 commit message 中删除。

## 操作流程

1. 先执行 `git branch --show-current` 和 `git status --short`，确认当前分支和工作区状态。
2. 明确列出当前会话实际修改过的文件。
3. 从 `$ARGUMENTS` 中提取被提到的文件，解析成仓库内的唯一文件路径。
4. 将“当前会话修改文件”和“备注提到且当前有改动的文件”合并成最终提交范围。
5. 如果当前会话修改文件无法可靠识别，或备注提到的文件解析存在歧义，先停下来向用户确认。
6. 如果最终提交范围为空，直接告知用户，不要创建空提交。
7. 只对最终提交范围执行 `git add <files...>`。
8. 用清洗后的备注 + AI 署名尾注作为 commit message。

## 提交备注规则

1. 优先使用 `$ARGUMENTS` 生成 commit message。
2. 先从 `$ARGUMENTS` 中删除所有已识别文件的原始文本片段，再整理多余空格、顿号、逗号、分号、括号和重复分隔符。
3. 如果 `$ARGUMENTS` 包含多行，只取清洗后的第一行作为标题。
4. 不要擅自改写备注核心含义；只做“删除文件名”和“最小必要清洗”。
5. 如果清洗后备注为空，先向用户索要新的提交备注，不要自行编造。
6. 如果项目或系统另有强制的 commit message 规范，在不改变备注核心含义的前提下做最小必要调整。
7. **严格保留备注中的换行符和空格格式**：commit message 必须按用户输入的原始格式呈现，不得合并换行、删除缩进或压缩空白字符。应使用 `git commit -F <tmpfile>` 方式提交，防止 shell 对换行符的转义和吞并。
8. **显式换行标记还原**：如果备注中包含字面量 `\n`（反斜杠 + n），在写入 commit message 文件时必须将其替换为真实换行符。这是因为 Bugfix 简报等模板使用 `\n` 作为显式换行标记，用户从聊天中复制粘贴时原始换行会被聊天框吞掉，需要通过此标记还原多行格式。

## AI 署名尾注规则

1. 在最终 commit message 末尾追加一个空行，再追加一行 AI 署名尾注。
2. 优先调用 `auto-ai-coauthor` skill 追加署名（若该 skill 存在且可用）。
3. 若 `auto-ai-coauthor` skill 不存在或不可用，则自行追加：`AI-Co-Authored-By: {AGENT_NAME}`，其中 `{AGENT_NAME}` 为当前执行提交的真实 AI Agent 名称。
4. commit message 示例：
   ```
   [bugfix] 修复HDR角标不显示的问题

   AI-Co-Authored-By: Claude Sonnet 4.6
   ```

## Git 动作

1. 在当前分支执行提交，不创建临时分支。
2. 提交成功后，执行 `git push origin <当前分支>`。
3. 如果远端不存在同名分支，则执行能把当前分支推上去的最小必要 push 命令，但仍然禁止新建本地分支。

## 输出要求

1. 明确告知用户本次使用的分支名。
2. 明确告知用户本次提交的文件列表。
3. 明确告知用户从备注里识别出的文件列表，以及其中哪些因未改动而未提交。
4. 明确告知用户清洗前备注和清洗后备注（含 AI 署名尾注）。
5. 明确告知用户提交结果和 push 结果。
6. 给出提交后的 commit SHA。
