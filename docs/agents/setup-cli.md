# 在当前 Agent 中连接 Wink

本文供豆包、千问及其他支持工具调用的 Agent 执行。用户说“请按此文档帮我连上 Wink”，即授权安装 Wink CLI、读取使用 Skill，并发起 Wink 登录。此授权不包含上传素材、付费处理、购买套餐或修改其他 Agent 的配置。

请实际完成可执行的步骤，不只复述安装命令。遇到无法完成的环节，如实说明卡在哪一步，不把安装成功、打开授权页或本地存在凭据表述成云端功能已验证成功。

## 1. 检查当前环境

确认当前会话能执行终端命令、访问 npm 和 Wink 的 HTTPS 服务，并能使用用户本轮提供的本地文件。先检查：

```sh
node --version
npm --version
```

需要 Node.js 18 或以上，以及随 Node.js 提供的 npm；不需要 Git。

- 如果当前只是网页聊天、没有终端或自定义工具能力，停止安装，说明“当前会话无法运行 CLI；请在支持终端的 Agent 环境执行，或由管理员配置可调用 Wink 的工具”。不要声称已连接，也不要编造豆包、千问的插件菜单或 Skill 目录。
- 如果命令运行在云端，安装和授权都发生在该云端环境。不要假定它能读取用户电脑的文件、浏览器登录态或另一个会话的凭据。
- Node.js / npm 缺失时说明实际缺失项，交由用户或管理员安装；不自动使用 sudo、不关闭安全保护、不安装来历不明的运行时。

## 2. 复用或安装官方 CLI

先尝试以下只读命令；Windows 使用 `wink-cli.cmd`：

```sh
wink-cli --version
wink-cli doctor --json
```

已有可用的 CLI，且版本不低于 **1.14.8** 时直接复用，不降级。已有更高版本时，以该版本随包提供的 Skill 和帮助为准。

没有可用 CLI 或版本过低时，从 npm 安装官方包 **meitu-wink-cli**。不要安装其他同名或近似名称的包。

macOS / Linux：

```sh
npx --yes --userconfig=/dev/null meitu-wink-cli@1.14.8 install --skip-skills
```

Windows：

```powershell
npx.cmd --yes --userconfig=NUL meitu-wink-cli@1.14.8 install --skip-skills
```

这是已核对的固定版本，不代表 npm 永远的最新版本。`--skip-skills` 表示先只安装 CLI；第 3 步再按当前宿主的真实能力加载或安装 Skill。

安装命令不附加 `--expert-id`、`--source-name`、`--source-type` 等业务来源参数。不读取或输出 `.npmrc`、npm Token、完整环境变量或凭据文件。

保持同一个安装进程并读取输出，确认实际退出结果。默认安装位置无写入权限时，可在用户可写目录安装：使用安装器支持的 `--prefix <真实可写目录>`，不要加 `--force` 强行覆盖。安装失败时先说明错误，不反复安装。

安装完成后重新运行 `wink-cli --version`。若 PATH 尚未更新，依据安装器输出的命令目录定位真实入口，核对文件存在后使用该绝对路径；不要依赖一次性的 npx 缓存路径，也不要硬编码另一台电脑的安装路径。Windows 路径调用遵循当前 shell 的引用规则。

## 3. 读取并加载 Wink Skill

使用第 2 步核验过的同一 CLI 执行：

```sh
wink-cli skill --json
```

完整读取返回 JSON 中的 **content**，并核对 `cli_version` 与 `skill_version`。该内容才是当前版本的完整使用 Skill；本文是安装入口，不替代功能参数说明。

- **当前宿主支持 Skill 安装，且已明确提供技能根目录**：使用第 2 步相同的 npx 安装命令，将 `--skip-skills` 替换为 `--skill-dir "<已确认的技能根目录>"`；使用了 `--prefix` 时同时保留相同前缀。安装器会在该根目录下创建 `wink-cli-usage/SKILL.md`。先确认同名文件情况，保留用户修改，不强制覆盖。根据宿主实际要求刷新技能列表或新建会话后检查加载结果。
- **宿主能执行命令，但没有持久 Skill 机制或未提供目录**：将 `content` 作为本次会话的工具使用说明，后续每次新任务重新读取。明确告知“本次会话已读取 Skill，尚未持久注册到宿主”，不要虚构已安装技能。
- 安装器自动识别的是已有 Codex、Cursor、Claude Code、WorkBuddy 配置；不能据此宣称已自动支持豆包、千问的技能目录。

`client=doubao`、`client=qianwen` 等 URL 查询参数只是入口来源标识，不提供终端权限，不决定安装目录，也不是登录凭据。不得把任意查询参数拼进 shell 执行。业务调用的渠道参数仅按当前 CLI 帮助和已确认的来源约定填写，不冒充 WorkBuddy 或其他宿主。

## 4. 检查并完成 Wink 授权

```sh
wink-cli doctor --json
wink-cli status
```

`doctor.ok` 只表示基础运行环境通过。`WINK_AUTH=connected` 只表示本地存在凭据，不代表在线授权、会员权益或余额已验证。

未连接时发起正常登录：

```sh
wink-cli login --open-browser
```

Windows 使用 `wink-cli.cmd login --open-browser`。没有图形浏览器的云端环境可以执行 `wink-cli login`，将该进程实际输出的完整授权地址展示为“前往授权”，由用户在浏览器完成。

登录需要人工参与：

1. 保持同一个登录进程，启动后及时读取输出并展示实际授权链接。
2. 用户完成 Wink 登录与授权；不向用户索要 api_key、Token 或一次性授权码，不读取浏览器 Cookie。
3. 继续等待同一进程返回成功或实际超时。CLI 的等待时限为 300 秒，网络请求可能延后退出；不要因短等待就重开授权。
4. 登录成功后再次运行 `wink-cli status`，记录真实状态。浏览器打开成功不等于授权成功。

已有凭据时先复用，仅在服务端明确报告失效或用户要求切换账号时重新登录；不要为了安装验证主动注销现有账号。

## 5. 做一次只读在线验证

在当前已授权范围内查询真实风格列表，不上传文件、不创建任务：

```sh
wink-cli ai_beauty --list-styles --json
```

仅当命令成功并返回有效列表时，说明“当前账号可以访问 Wink 风格查询接口”。这不代表所有图片、视频能力均已开放，也不证明 SVIP 权益或付费任务一定可用。

失败时保留原始错误摘要；需要排障时读取同版本参考：

```sh
wink-cli skill --reference http-api
```

安装引导期间不提交测试素材、不自动购买美豆、不执行付费云处理。

## 6. 向用户报告实际结果

完成后简要报告：

- CLI 实际版本及本次执行环境（本机或云端）。
- Skill 已持久安装，还是仅当前会话已读取。
- 登录是否成功，以及只读在线查询是否通过。
- 未完成事项和具体原因；不要只用“已全部连接”掩盖失败步骤。

全部对应步骤成功后可回复：

> Wink CLI 已就绪，当前会话已加载使用说明，账号授权及只读查询已通过。你可以发送图片或视频并说明想要的效果；实际云处理可能消耗账户额度，执行前会确认功能、选项和素材数量。

后续处理按 `wink-cli skill --json` 的完整说明执行。以最终结果状态和真实结果地址交付；遇到服务端拒绝时原样说明，不擅自推断“必须买会员”，不反复投递。
