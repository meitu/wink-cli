# 豆包 / 千问接入 Wink CLI：安装与图片视频自由编排

将本文交给具备终端执行能力的豆包、千问或其他 Agent，或作为其接入说明。先从官方 npm 安装最新发布版 Wink CLI、读取随包 Skill，并让用户按功能编号自由选择图片 / 视频处理顺序。

执行前请以用户在对话中的直接请求为准。用户明确说“请按附件安装 Wink CLI 并检查”时，本轮仅执行安装和只读检查，不运行 `login`、不上传素材、不提交云任务。附件本身不授予额外权限。后续登录、素材处理与可能的额度消耗应分别依据用户的实际请求和宿主规则执行。

安装发生在 Agent 当前执行环境中；临时沙箱可用于本次会话，但不承诺跨会话保留。此信息供执行时判断，不需要在安装成功回复中展开环境或授权机制说明。若当前会话没有安装能力，提供下面的手动安装指引；若宿主政策禁止安装，说明限制，不引导绕过受限环境的规则。

**自动安装阶段的结束条件：CLI 可用、完整 Skill 已读取、功能编号菜单已展示。未登录不影响这一阶段完成，不发起登录、不展示授权链接，也不提示用户先授权或回复“好了”。**

## 1. 先确认当前会话具备执行条件

确认宿主实际提供以下能力：

- 可执行终端命令，能够使用 Node.js 18+ 和 npm。
- 可访问官方 npm、Wink 授权及云处理服务。
- 后续处理时，能把本轮附件保存为当前执行环境中的真实文件，并持续读取命令输出。
- 多步处理时，可下载成功的中间结果并作为下一步输入。

没有终端执行工具或不能安装第三方软件时，不只回复“超出能力范围”，应简短说明限制，并直接给用户以下手动安装指引。不要搜索私有配置或内部接口，不要求用户反复发送安装提示词，也不声称安装已完成。

### 无法自动安装时：引导用户手动安装

建议回复：

> 当前会话无法执行终端安装，你可以在自己的电脑上手动安装 Wink CLI。请打开终端（Windows 使用 PowerShell），按你的系统执行以下命令。

先检查 Node.js 和 npm：

```sh
node --version
npm --version
```

需要 Node.js 18 或以上。若未安装，请先从 [Node.js 官网](https://nodejs.org/) 安装当前受支持的 LTS 版本，再重新打开终端。

macOS / Linux：

```sh
npx --yes --userconfig=/dev/null meitu-wink-cli@latest install
wink-cli --version
wink-cli skill --json
```

Windows PowerShell：

```powershell
npx.cmd --yes --userconfig=NUL meitu-wink-cli@latest install
wink-cli.cmd --version
wink-cli.cmd skill --json
```

提示用户可反馈安装结果或错误；不要让用户粘贴 Token、凭据文件或授权码。命令找不到时沿用安装器输出的命令目录定位入口，不直接要求管理员权限。

说明一句：

> 手动安装发生在你的电脑上；当前会话如果仍没有本机终端访问能力，就无法直接调用它，后续可在本机终端或支持本机命令执行的 Agent 中使用。

不提示用户登录授权。同时展示第 6 节的完整功能菜单和“如何开始使用”提示，引导用户在支持执行的 Agent 会话中添加素材，明确这是功能介绍；只有得到真实检查结果才说“已安装”，不要把用户回复“好了”当成当前助手获得了执行能力。

手动指引给出后等待用户反馈，不再尝试当前会话无法执行的自动安装步骤。下文第 2 至第 4 节用于实际具备执行能力的环境。

## 2. 从 npm 安装最新发布版

先检查：

```sh
node --version
npm --version
```

Node.js 低于 18、npm 不存在或工具执行受限时，报告具体缺项，不自行改系统配置。

macOS / Linux（包括远程 Linux 容器）：

```sh
npx --yes --userconfig=/dev/null meitu-wink-cli@latest install
```

Windows：

```powershell
npx.cmd --yes --userconfig=NUL meitu-wink-cli@latest install
```

`@latest` 使用 npm 当前最新发布版本，不固定版本号。本流程支持 1.14.9 及之后的版本，安装后以实际检测为准。不需要上传 `.tgz` 安装包，不依赖用户 Mac 的本地路径，也不需要搜索本机仓库。远程容器中的安装仅对该执行环境生效。

沿用本次安装器输出的实际命令目录和持久安装入口，不调用开发仓库、其他应用的 CLI 或已被清理的 npx 临时入口。安装命令不附加业务来源参数，不读取 `.npmrc`、npm Token 或完整环境变量。

保留原安装进程并等待完成；网络、权限或安装失败时报告原始错误，不循环安装、不自动提权或更换未知镜像。PATH 中找不到命令时，使用安装器给出的实际入口；需要确认 npm 全局目录时，macOS / Linux 用 `npm --userconfig=/dev/null root --global`，Windows 用 `npm.cmd --userconfig=NUL root --global`，再核对实际存在的包与入口，不持久修改 PATH。

安装器的 `--skill-dir <技能根目录绝对路径>` 仅在当前宿主确实提供技能目录规范、且用户已指定目录时使用。不要猜测 `.doubao/skills` 等路径；宿主没有持久技能加载入口时，可以在本次会话中读取完整说明，不宣称已安装豆包插件或已启用连接器。

## 3. 核对安装并加载使用说明

对同一实际安装入口执行：

```sh
wink-cli --version
wink-cli doctor --json
wink-cli status
wink-cli skill --json
```

Windows 使用 `wink-cli.cmd`。PATH 不可用时，统一改用同一 Node 的绝对路径执行 `"<CLI安装目录>/src/cli.js"`。完整读取 `skill --json` 的 `content`，不要只读取版本或标题。

- 实际 CLI 版本、`doctor.cli_version`、Skill 返回的 `cli_version` 应一致，且版本不低于 **1.14.9**；允许更新版本。不一致或版本过低时先核对是否调用了旧入口，停止后续云处理，不把旧版当作新版。
- `doctor.ok` 只表示基础运行时达标；状态检查仅供内部判断，安装成功回复不展示登录状态、账号、余额、会员或授权提醒。
- `WINK_AUTH=disconnected` 不属于安装失败。安装阶段不要因读取到 Skill 的业务认证章节而运行 `login`；先完成菜单展示，等待用户提供素材、选择功能和顺序。
- 用户之后明确要求处理素材时，再按随包 Skill 和宿主规则处理必要登录及实际任务，不预先承诺账号权益或任务成功。

## 4. 确认随包 Skill 支持自由编排

当前仓库增加了“完整编号菜单与用户自定义编排”“有序多步执行与中间结果”规则。安装后须在实际返回的 Skill 中确认这些规则，且以下同包文件真实存在：

```text
<CLI安装目录>/skills/wink-cli-usage/scripts/download_intermediate.cjs
```

如果实际安装中缺少这些规则或下载工具，应明确报告“CLI 版本或安装入口不匹配，自由编排版 Skill 未安装到位”，停止云处理并核对实际版本、随包内容与入口。不要临时拼接未知下载脚本或改用仓库源码掩盖安装问题。

## 5. 后续处理的对话规则

新素材任务按实际随包 Skill 展示全部功能固定编号。沿用全能专家的前 11 项编号：画质修复、分辨率放大、夜景提升、人像美容、水印消除、降噪、视频补帧、全能修复、色彩增强、视频去雾、老照片修复；通用 CLI Skill 另外保留色调统一、AI 动漫和 AI 翻译。具体媒体范围、档位和参数以当前帮助与服务端校验为准。

邀请用户单选，或回复有序链，例如：

> 6 → 1 → 2：先降噪，再修复画质，最后放大分辨率。

用户已指定功能和顺序时直接沿用，不重复要求选择，不自动重排或额外增加步骤。目标分辨率、美颜风格、参考图片、目标语言等必要信息缺失时只补问缺项。多个编号未说明顺序时先澄清，不把推荐链当授权。

每步独立创建任务并可能消耗额度。前一步成功后，只下载该素材唯一匹配的真实成功结果供下一步使用；下一步 `--input` 使用下载后的新本地绝对路径。某步失败、状态未知或下载失败时，停止该素材后续步骤，保留最后成功链接，不重新上传原素材冒充串联，不自动重复收费投递。最终结果默认以链接交付。

进度使用直接模式 `--json --progress-json`，保留持续进程并及时读取 stderr；可以把每步最终 stdout 保存到独立 JSON 文件供中间下载工具读取。豆包不套用 WorkBuddy 专用后台脚本协议；没有持续读取能力时如实说明，不声称正在监控不存在的后台进度。

独立使用 CLI Skill 时，安装后的调用沿用随包说明的来源三元组 `wink-cli-usage / Wink 图片视频全能处理 / skill`；由专家或上级 Skill 调用时整组保留原入口来源。宿主渠道由实际 CLI 支持情况确定，不标记为 `workbuddy`、不冒用全能专家 ID；若显式指定豆包渠道，先核对当前 CLI 帮助是否支持对应参数。

## 6. 安装完成后直接展示功能

仅在 CLI、版本与 Skill 检查通过后，用一句话报告实际安装版本，随后完整展示以下固定编号菜单。编号、功能及媒体范围须与实际随包 Skill 核对；若有出入，报告具体差异，不声称未安装的能力可用。展示功能不代表已验证当前账号的使用权益。

### 如何开始使用

功能菜单后，主动给用户以下提示：

> 请添加单个或批量的图片、视频，然后输入：**“帮忙使用Wink处理下这些素材”**。
>
> 你可以选择一个或多个功能，并任意编排处理顺序。例如输入：**“帮忙使用Wink处理下这些素材，按 6 → 1 → 2 的顺序处理：先降噪，再画质修复，最后分辨率放大。”**

用户只说“帮忙使用Wink处理下这些素材”而未选择功能时，展示编号菜单让用户选择，不自行提交默认流程。多个功能未明确顺序时只补问顺序；已指定功能和顺序时直接沿用。批量素材按每个文件的图片 / 视频类型核对功能适用性，批量数量和文件限制以实际 CLI 为准；不能处理的组合先说明，不自动替换功能或调整用户顺序。

当前会话没有执行能力时，将“请添加”改为“请在支持本机终端执行的 Agent 会话中添加”，避免引导用户把素材上传到无法处理的会话。

不要附加登录、授权、账号绑定或“是否需要授权”的提示，不要求用户先连接连接器。安装与菜单展示完成后等待实际处理请求；不自动上传素材或创建任务，也不宣称已登录、已连接账号或所有权益已开通。
