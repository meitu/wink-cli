# 豆包接入 Wink CLI：本地测试安装与图片视频自由编排

将本文交给具备终端执行能力的豆包 Agent，或作为其接入说明。本次先安装本机打包的 Wink CLI **1.14.9 测试版**、读取随包 Skill，并让用户按功能编号自由选择图片 / 视频处理顺序。

本文只授权安装和只读检查，不包含账号登录、素材上传、付费云处理或购买套餐。用户后续明确要求处理素材时，再按所选功能、顺序与参数执行。

## 1. 先确认当前会话具备执行条件

确认宿主实际提供以下能力：

- 可执行终端命令，能够使用 Node.js 18+ 和 npm。
- 可访问官方 npm、Wink 授权及云处理服务。
- 后续处理时，能把本轮附件保存为当前执行环境中的真实文件，并持续读取命令输出。
- 多步处理时，可下载成功的中间结果并作为下一步输入。

没有终端执行工具时，立即说明“当前会话无法安装或运行 CLI，需要在具备终端的 Agent 环境接入”。不要把阅读 Markdown 说成安装成功，不搜索本机私有配置、不猜测豆包的内部工具，也不要求用户反复发送安装提示词。远程 MCP 是另一条接入路线，不能仅通过改提示词获得。

## 2. 安装本地 1.14.9 测试包

先检查：

```sh
node --version
npm --version
```

Node.js 低于 18、npm 不存在或工具执行受限时，报告具体缺项，不自行改系统配置。

当前测试电脑（macOS）的本地安装包：

```text
/Users/lixingping/workspace/wink-cli/dist/meitu-wink-cli-1.14.9.tgz
```

先确认这个文件真实存在，然后执行：

```sh
test -f "/Users/lixingping/workspace/wink-cli/dist/meitu-wink-cli-1.14.9.tgz"
npx --yes --userconfig=/dev/null "/Users/lixingping/workspace/wink-cli/dist/meitu-wink-cli-1.14.9.tgz" install
```

如果文件不存在，停止并报告缺少本地测试包，不继续执行安装命令。其他电脑或远程执行环境访问不到这台 Mac 的路径；需先将同一个 `.tgz` 测试包复制到实际执行环境，再使用它的真实绝对路径安装。Windows 对应命令为 `npx.cmd --yes --userconfig=NUL "<测试包的实际绝对路径>" install`，不要照抄 Mac 路径。

本次不使用 `meitu-wink-cli@latest` 或 `@1.14.9` 从 npm 安装：1.14.9 尚未发布到 npm，`latest` 暂时不包含本次修改。安装器会将本地测试包持久安装，不需要直接运行仓库源码。沿用本次安装器输出的实际命令目录和持久安装入口，不调用其他应用的 CLI 或已被清理的 npx 临时入口。安装命令不附加业务来源参数，不读取 `.npmrc`、npm Token 或完整环境变量。

保留原安装进程并等待完成；网络、权限或安装失败时报告原始错误，不循环安装、不自动提权或更换未知镜像。PATH 中找不到命令时，使用安装器给出的实际入口；需要确认 npm 全局目录时，macOS / Linux 用 `npm --userconfig=/dev/null root --global`，Windows 用 `npm.cmd --userconfig=NUL root --global`，再核对实际存在的包与入口，不持久修改 PATH。

安装器的 `--skill-dir <技能根目录绝对路径>` 仅在豆包宿主确实提供技能目录规范、且用户已指定目录时使用。不要猜测 `.doubao/skills` 等路径；宿主没有持久技能加载入口时，可以在本次会话中读取完整说明，不宣称已安装豆包插件或已启用连接器。

## 3. 核对安装并加载使用说明

对同一实际安装入口执行：

```sh
wink-cli --version
wink-cli doctor --json
wink-cli status
wink-cli skill --json
```

Windows 使用 `wink-cli.cmd`。PATH 不可用时，统一改用同一 Node 的绝对路径执行 `"<CLI安装目录>/src/cli.js"`。完整读取 `skill --json` 的 `content`，不要只读取版本或标题。

- 实际 CLI 版本、`doctor.cli_version`、Skill 返回的 `cli_version` 应一致，且本次均须为 **1.14.9**。不一致时先核对是否调用了旧入口，停止后续测试；不要改用 npm 旧版。
- `doctor.ok` 只表示基础运行时达标；`WINK_AUTH=connected` 只说明本地已有凭据，不证明在线授权、SVIP 权益或余额有效。
- 输出 `WINK_AUTH=disconnected` 时，安装仍可完成；现在不提前登录。收到具体处理请求、需要账号授权时，按随包 Skill 执行 `login --open-browser`，保留同一进程，由用户完成真实网页授权。
- 无终端打开浏览器能力时，展示 CLI 本次生成的完整授权链接；不可伪造链接、索要密钥或让用户提供授权码。
- 没有对应正式查询工具时，不编造当前登录账号、剩余美豆或会员状态，不读取凭据文件。

## 4. 确认随包 Skill 支持自由编排

当前仓库增加了“完整编号菜单与用户自定义编排”“有序多步执行与中间结果”规则。安装后须在实际返回的 Skill 中确认这些规则，且以下同包文件真实存在：

```text
<CLI安装目录>/skills/wink-cli-usage/scripts/download_intermediate.cjs
```

如果实际安装中缺少这些规则或下载工具，应明确报告“本地测试包或安装入口不匹配，自由编排版 Skill 未安装到位”，停止云处理测试并核对安装包与入口。不要要求先发布 npm 才能本地测试，也不要临时拼接未知下载脚本或改用仓库源码掩盖安装问题。

## 5. 后续处理的对话规则

新素材任务按实际随包 Skill 展示全部功能固定编号。沿用全能专家的前 11 项编号：画质修复、分辨率放大、夜景提升、人像美容、水印消除、降噪、视频补帧、全能修复、色彩增强、视频去雾、老照片修复；通用 CLI Skill 另外保留色调统一、AI 动漫和 AI 翻译。具体媒体范围、档位和参数以当前帮助与服务端校验为准。

邀请用户单选，或回复有序链，例如：

> 6 → 1 → 2：先降噪，再修复画质，最后放大分辨率。

用户已指定功能和顺序时直接沿用，不重复要求选择，不自动重排或额外增加步骤。目标分辨率、美颜风格、参考图片、目标语言等必要信息缺失时只补问缺项。多个编号未说明顺序时先澄清，不把推荐链当授权。

每步独立创建任务并可能消耗额度。前一步成功后，只下载该素材唯一匹配的真实成功结果供下一步使用；下一步 `--input` 使用下载后的新本地绝对路径。某步失败、状态未知或下载失败时，停止该素材后续步骤，保留最后成功链接，不重新上传原素材冒充串联，不自动重复收费投递。最终结果默认以链接交付。

进度使用直接模式 `--json --progress-json`，保留持续进程并及时读取 stderr；可以把每步最终 stdout 保存到独立 JSON 文件供中间下载工具读取。豆包不套用 WorkBuddy 专用后台脚本协议；没有持续读取能力时如实说明，不声称正在监控不存在的后台进度。

独立使用 CLI Skill 时，安装后的调用沿用随包说明的来源三元组 `wink-cli-usage / Wink 图片视频全能处理 / skill`；由专家或上级 Skill 调用时整组保留原入口来源。宿主渠道由实际 CLI 支持情况确定，不标记为 `workbuddy`、不冒用全能专家 ID；若显式指定豆包渠道，先核对当前 CLI 帮助是否支持对应参数。

## 6. 安装结束时简短汇报

如实列出：实际安装版本、CLI 检查是否通过、当前 Skill 是否包含自由编排与下载工具，以及是否需要后续授权。

例如，在对应检查均通过时：

> Wink CLI 本地测试版 1.14.9 已安装，已读取支持编号编排的使用说明。现在没有上传素材或创建任务；后续处理时按需完成账号授权。你可以发送图片或视频，选择单个功能或指定处理顺序。

只完成 CLI 安装，不宣称豆包平台插件、WorkBuddy 连接器或所有云处理权益均已开通。
